# 旁路禁封命运说明（当班封死）

编号：旁路禁封第3号 · 旁路案丙（BP-C09）
日期：2026-11-24
口径：**旁路开放禁封闸**。两边不得混用，禁止旁门第三路，禁止只改快照页角标色。

## 选定路径：甲路径（禁封回滚）

旁路挂起仍开放时，封闸正式快照**零增**并**拒写回滚**：

- 封闸服务对票态 `旁路挂起` 或存在 `overload_holds.status='开放'` 的票，一律 409 拒封。
- 拒封时 `gate_seals` 零行增、`weigh_tickets.generation` 零升、票态零改，业务事务回滚。
- 拒封须独立落审计命书：action=`seal_blocked_bypass`，payload 含「禁封偏航拒写」，
  命书在独立事务提交，不随业务回滚而消失。

## 禁止事项

- 乙路径（封闸只许影子快照草稿、待旁路闭环后晋升正式）**不采用**。
  封闸写口在旁路开放期不得新增任何快照行（含草稿）；既存影子草稿仅作历史数据保留，
  旁路闭环后须经正式封闸晋升，草稿本身零改、永不自动转正。
- 禁止第三路：不得放行、不得改票态绕挂、不得跳过占票锁。
- 禁止只改快照页角标色：前端只展示后端同源状态，禁封判定全部在服务端。
- 偏离即记「禁封偏航拒写」并拒写。

## 占票锁与争用

- 双会话同时对同票（如 BP-C09）抢封闸，须以 `pier_locks` 占票锁 `ticket:{id}` 串行。
- 后到者 409，只写 `contention_log` 争用痕，不写业务；争用痕独立事务落库。
- SQLite 占锁写入撞主键时按争用处理（记痕 + 409），不得冒泡 500。

## 五页核账同源

快照（seal）、超重（overload）、过磅（tickets）、血缘（lineage）、对账（reconcile）
对「旁路是否开放」「快照是否正式」的判定共用同一 SQL 口径：

- 旁路开放：`overload_holds WHERE ticket_id=? AND status='开放'`
- 正式快照：`gate_seals.status='已封闸'`；`影子快照草稿` 不计封、不计对账证明。

## 失败测链（禁止跳过）
